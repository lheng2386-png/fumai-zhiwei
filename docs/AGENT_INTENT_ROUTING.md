# 智能体问题意图分流

普通问答在设备证据查询与模型调用之前分流，所有同步、异步入口使用相同规则。

| 问题 | 行为 |
|---|---|
| “你是什么模型？”“你是谁？” | 系统直接回答，模型名称取运行中的适配器配置，不调用模型自我介绍 |
| “你能做什么？”“你能分析哪些设备异常？” | 直接介绍助手功能，不查询样例事件 |
| “怎么使用你？”“帮助” | 直接给出操作方法 |
| 招呼、无关问题 | 简短回复或说明使用范围，不触发证据分析 |
| 设备、事件、功率、异常、核查等运维问题 | 保留原有证据分析、Qwen 工具调用和进度流 |
| “你是什么模型？顺便分析 inv_07 的异常” | 先保留身份说明，再执行明确提出的运维分析 |

选中的事件/设备不会把身份和帮助问题强行转成设备分析；仅在“分析一下”等运维省略表达中使用选中上下文。普通回答不占分析名额，名额耗尽时仍可回复身份或帮助。

直接回答沿用原有对话审计和任务身份隔离，异步入口立即返回 `status=completed`，SSE 可以正常读取 `event: done`。没有模型/证据工具调用，其 `trace`、`events` 与 `evidence_ids` 均为空；不附带站点数据版本，也不允许生成工单草稿。

直接回答字段：`response_type=direct`、`intent=identity|capabilities|help|greeting|out_of_scope`、`engine=direct`、`model_status=not_invoked`。`model_name` 是当前配置名称，不表示本次发起了模型请求。运维回答为 `response_type=analysis,intent=maintenance`，保留已有字段兼容历史记录。前端据此显示普通对话，不渲染异常证据卡。

前端离线样例预览也遵循同一分类契约，身份回答明确无法确认服务器当前模型；不使用旧缓存冒充当前配置。分类是显式规则，不是通用语义分类器；未识别的无关表述会提示补充运维范围。

验证命令：

```bash
python -m unittest discover -s agent/tests -v
node frontend/tests/intent.test.mjs
```

新增测试覆盖 32 组前后端共同分类用例、身份/功能/帮助不访问证据或模型、真实 HTTP 与 SSE、并发已满时直接回答、异步幂等和权限隔离、无模型配置、选中事件上下文、运维及混合请求仍调用模型、普通问答不能生成草稿、前端普通对话渲染和 HTML 转义。
