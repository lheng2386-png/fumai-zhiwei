# GPVS-Faults 跨运行模式时序基线

本实验检验：在实验室并网光伏系统的一种运行模式中训练的故障检测器，切换到另一种模式后是否仍可区分故障。数据来自 [GPVS-Faults](https://doi.org/10.17632/n76t439f65.1)（CC BY 4.0）。它与 La Réunion 屋顶逆变器数据的设备、故障和采样率都不同，**不是原模型的跨场站验证**，不能合并标签后宣称工业泛化。

## 数据与标签边界

- 16 个 CSV：`F0` 为无故障，`F1`–`F7` 是七种注入故障；`L`/`M` 分别是限功率 IPPT 和最大功率 MPPT。每个故障和模式只有一次约 7–14 秒的实验。
- 源文件 SHA-256 在本地 `data/raw/gpvs_faults/manifest.json`；ZIP CRC 已通过。每文件有 `Time` 和 13 个电气通道，没有逐行故障标签。发布方仅说明故障约在实验中途注入，未给每个文件精确时间戳。
- 因此对 `F1`–`F7`，只把**完全落在前 1/3** 的 0.2 秒非重叠窗口暂记为健康、**完全落在后 1/3** 的窗口暂记为故障，其余窗口丢弃。`F0` 全段暂记健康。这是保守的代理标签，不等于已验证的故障起止记录。
- 源 readme 声称平均采样约 10 微秒；实际 16 个 CSV 的时间列中位间隔均约 **100 微秒**（约 10 kHz）。实验按时间列分窗，不按 readme 的频率常数分窗。

## 划分、特征和阈值

固定两次方向：全部 `L` 实验训练、全部 `M` 实验测试；再反过来。所有同一次实验的窗口只在一侧。每个通道取中位数、四分位距、95–5 分位跨度、RMS、标准差；不使用绝对时间。固定 ExtraTrees（500 树、最小叶节点 2、`max_features=sqrt`、类别平衡、种子 2032），不根据目标模式测试结果调参。

比较原始特征和“健康参考扣除”：对每个实验，只用其**已知注入前的前 1/3** 窗口求特征中位数，再从同实验所有窗口特征中扣除。后者需要现场有可确认的健康启动段；如果没有这种校准条件，这个改进不能直接用于生产。每个训练方向再按**整次实验留一**取得源模式训练窗口的折外分数，用健康窗口第 99 百分位设告警阈值，然后固定模型与阈值评估目标模式；目标模式没有参与阈值选择。

复现：

```bash
python3 src/fetch_gpvs_faults.py
python3 src/benchmark_gpvs_modes.py --output reports/gpvs_mode_transfer_v4.json
```

健康参考提高了跨模式 AP，但没有解决可靠告警：参考扣除后，L→M 的 F3、F4、F6 故障各只检出 2、3、3 个窗口；M→L 的 F4 **1/24**，F1/F7 各只检出 7/21、5/24。窗口重叠虽已避免，仍是同一次短实验中的强相关测量；百分比不能当成独立场站的置信度。目标模式正常窗口告警率即使只有 2%–3%，按 0.2 秒窗口连续运行也不能直接接受。需要更长的正常运行、准确注入时间、独立设备及真实故障工单来评估事件级召回与每设备每天误报数。不要为提高这张表的目标模式成绩反复调参；这里的目标模式现已被查看，未来模型比较需另找留出数据。
