## 项目主题与边界

建议主题：**AI 与三维空间交互 + 光伏设备功率异常辅助核查**。

目标用户是需要从设备时序数据中筛选线索、核对证据并安排人工复核的光伏运维人员。解决的问题是：设备多、曲线分散，事件、设备位置与核查依据难以对应。参考功率采用同时刻天气观测，不能称为未来发电量预测；候选筛查也不是提前预测故障。

本版选择 Three.js / WebGL2，在现有 Web 产品中直接连通设备编号与事件；无需额外 Unity 播放器。Wasm 用于可选 Meshopt 几何解码。每项技术的作用、模型接入格式及资源回收见 [三维接入说明](SCENE3D_INTEGRATION.md)。选型不依赖某一品牌建模工具。

## 可操作的 3–5 分钟演示

先启动 `frontend/serve.mjs` 或登录团队的已部署网站，进入 `/#scene`。本地孤立运行若缺少认证服务会重定向登录；自动浏览器测试只在 127.0.0.1 模拟认证，部署版仍走正常登录。

1. **输入一个具体问题。**点“单机功率偏离”，读事件编号和设备编号。在场景红色气泡或右侧索引中找到 inv_07，点击后确认定位。错误设备会提示重新核对。
2. **核对本条事件的证据。**展开 DEMO-2107-001 的观测：9.4 / 27.8 kW，均值差 18.4 kW，6 个有效点跨 25 分钟，23 台有效其他同群。选择证据支持的单机候选。这里的均值差不等于每个点都超阈值；连续性来自样例事件的已定义字段。不能将功率差解释成通信丢包或已确认故障。
3. **作出受证据约束的决定。**写明已知现象和待补告警、检修等材料，选择“待进一步核查”。可打开智能体询问依据；打开不会自动调用模型，该环节需要网络和模型服务。
4. **输出与复盘。**下载本地 JSON，查看样例来源、事件、选择历史、备注及本次耗时。该文件不是正式工单，不写业务复核、不确认故障、不控制设备、不发送通知。切换页面、刷新或退出后演练状态清除，下载前页面有明确说明。
5. **展示边界条件。**再点“同群证据不足”，定位 inv_22。只有 3 台有效其他同群，必须先补数据再归因；不能照搬上一个案例的结论。此案例用于展示数据质量约束。

没有 WebGL 时，仍可通过设备索引完成同样流程。导入任意 JSON 场景后退出演练，避免将内置案例挂到未经验证的工程设备；刷新可恢复示意场景。

两个案例均为 `frontend/dist/data.js` 构造样例、程序化示意坐标和简化几何，不是实测电站、真实推理结果或高精度建模成果。新增导览只是演示核查交互。正式业务的人工复核、工单、维修及恢复验证需另行验收。

真实三模型联调沿用模型分支 `exp/gpu-model-validation` 的 `docs/COMPETITION_MODEL_INTERFACE.md` 与 `competition-inference-v1`；只有设备身份、观测来源、时段匹配后才关联，不能把三个不同公开数据源伪装成同一设备联合诊断。服务不可达时明确展示不可用，不用本页样例替代真实推理。

截至本轮部署前预检：智能体和业务健康接口正常，独立 `/model-api/health` 返回 502，不能宣称已在线跑通三模型闭环。这个前端任务不更改模型服务、认证、邮件或其他成员的后端。

## 建议的工程效果验证方法

先固定样本与正确映射，再让同一批体验者分别完成“列表方式”和“三维方式”的相同核查任务；交替体验顺序以减小学习效应。记录找到正确设备的比例、错误选择次数、完成时长中位数、能否正确拒绝证据不足的归因，以及设备/事件映射错误。记录样本量、浏览器、硬件、网络条件与版本。样本不足时只报告探索性结果。

异常识别效果单独使用带确认标签的留出事件，报告精确率、召回率与混淆情况，不能用 UI 正常运行证明识别准确率。功率参考残差也不能当作实际维修收益。现阶段未测得误报率降低、发电量提升或巡检效率提升，不写未经测试的百分比。
