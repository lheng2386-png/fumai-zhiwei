# La Réunion 时序故障模型：第一轮跨事件验证

本实验回答一个具体问题：在一座真实屋顶电站的历史数据中训练后，模型能否识别**之后发生的遮挡事件**，并且在长期正常运行时少报错？数据来自 [La Réunion 公开数据最新版](https://zenodo.org/records/7828879)（CC BY 4.0）。数据中的故障是人为设置的各类遮挡；结论不覆盖逆变器内部故障，也不代表跨电站部署效果。

## 数据与划分

- 故障逆变器约 299 万条电气记录，带 `Fault` 标签；另有同时记录的正常对照逆变器。第一轮 14 特征模型没有使用气象变量；完整气象文件现已下载并校验，增强实验正在准备。
- 每分钟取电气量中位数；使用故障机和对照机的功率、电流、电压、电网频率及两个比值，共 14 个特征。窗口长度 30 分钟、步长 5 分钟，只在对照机持续发电时取样。标准化只在训练窗口上拟合。
- **训练**：2021-10-01—2022-03-11；**验证**：2022-03-15—2022-04-03；**留出测试**：2022-04-19—2022-05-19；**正常运行压力检查**：2022-06-01—2023-04-13。窗口不跨自然日，分区之间留有空档。由于故障集中在 2022 年 2–5 月，不能简单按整段数据的 70/15/15 划分。
- 训练/验证/测试分别有 **8,716 / 1,842 / 2,853** 个窗口，其中故障窗口 **764 / 480 / 182** 个；另有 **27,666** 个后续正常窗口。训练区未出现的“遮挡组件三分之一（3.1）”出现在留出测试区。

可复现划分和原始文件校验值见 `data/processed/la_reunion_v1/manifest.json`（本地数据目录，不提交 GitHub）。预处理命令：

```bash
python src/prepare_reunion.py --raw-dir data/raw/la_reunion --output data/processed/la_reunion_v1
```

## 模型比较

在相同划分和三个随机种子下比较 ExtraTrees、自己实现的多尺度时序 CNN（约 12.9 万参数）和轻量 Transformer（约 18.7 万参数）。按验证集平均精度 AP 选模型，再在验证集上确定告警阈值；测试集直到选择完成后才读取一次。使用 Apple GPU (MPS) 完成这轮训练，结果和检查点保存在 `reports/reunion_v1_mps/`。

| 候选 | 验证集 AP |
| --- | ---: |
| ExtraTrees | 0.9705 |
| 多尺度 CNN，三个种子 | 0.9752 / 0.9675 / 0.9700 |
| CNN 三种子平均概率 | 0.9734 |
| Transformer，三个种子 | 0.9746 / **0.9774** / 0.9737 |
| Transformer 三种子平均概率 | 0.9742 |

依预定规则，选中 `transformer_seed2032`，验证集阈值为 0.05。验证集故障精确率 0.989、召回率 0.952。这些验证数值明显高于后面的留出测试，因此不能把验证成绩当作真实部署效果。

后来补做了两层双向 LSTM（约 21.1 万参数）对照：使用**同一训练/验证分区**、三个种子、最多 50 轮、早停耐心 8、批量 256、学习率 `8e-4`，只读取训练和验证文件。三种子验证 AP 为 **0.9671 / 0.9693 / 0.9681**，平均 **0.9682**，平均概率集成 **0.9686**；低于上表的 CNN/Transformer。LSTM 的结果属于已经多次使用过的开发验证期上的探索性比较，**没有读取留出测试或正常压力区**，不能因此重新挑模型再宣称旧测试是盲测。代码 `src/lstm_model.py`、`src/compare_reunion_lstm.py`，逐轮记录在本地 `reports/reunion_lstm_mps_v1/`。

按同样条件还补做了**普通双向 RNN**：三个种子验证 AP **0.9761 / 0.9760 / 0.9687**，平均 **0.9736**，三种子均值集成 **0.9708**。最佳普通 RNN 略高于最佳 CNN，但仍低于最佳 Transformer；三个种子的波动也提示不能只看一个最优数。脚本仍为 `src/compare_reunion_lstm.py`，加 `--architecture rnn`；本地结果在 `reports/reunion_rnn_mps_v1/`。

用已保存的验证分数又比较固定的等权集成，不重复训练或读取留出测试：Transformer 三种子平均 AP **0.9742**，CNN 三种子平均 **0.9734**，两者最佳单模型各占一半 **0.9751**，两种三种子均值各占一半 **0.9737**；均低于最佳 Transformer 单模型的 **0.9774**。按完整日期重采样 1,000 次，跨架构最佳单模型等权融合相对所选 Transformer 的 AP 差异中位数 **−0.0019**，95% 区间约 **[−0.0091, +0.0008]**。这个验证期只有 18 天且已经参与先前选择，故这里只说明**没有观察到稳定集成收益**，不通过反复调权重追求同一验证集分数。代码为 `src/compare_reunion_ensembles.py`，本地结果 `reports/reunion_ensemble_validation_v1.json`。

加入循环模型后，最佳 Transformer+最佳 RNN 等权 AP **0.9759**，Transformer+CNN+RNN 等权 **0.9753**，四架构最佳单模型等权 **0.9741**，仍未超过单个 Transformer。完整对照在本地 `reports/reunion_ensemble_four_arch_v1.json`。上述“最佳”单模型已经由同一验证期挑选，集成分数因此也是探索性结果，不作为新的无偏选模依据。

## 留出测试与长期误报

选定模型和阈值后，只进行了一次留出测试评估：

| 指标 | 结果 |
| --- | ---: |
| 测试集 AP | 0.734 |
| 测试集宏平均 F1 | 0.849 |
| 故障窗口召回率 | 175/182 = 0.962 |
| 故障窗口精确率 | 175/302 = 0.579 |
| 正常窗口误报率 | 127/2,671 = 0.0475 |
| 含故障日期检出 | 6/6 |
| 无故障测试日期出现告警 | 10/24 |
| 后续正常运行窗口误报 | 110/27,666 = 0.0040 |
| 后续正常运行日期出现告警 | 36/273 |

尤其需要复核 **2022-04-20**：该日官方标签均为正常，但产生 60 个误报窗口。这些窗口的故障机/对照机功率比中位数约 **0.74**，当天未报警窗口约 **0.87**。它可能是标签之外的真实低发电，也可能是天气、设备配置或模型偏差；没有现场记录，不能擅自改标签或把误报说成已确认故障。

**目前不适合直接用于生产告警。**要优先解决的是跨日期性能下降和误报，而非单纯增加模型参数。下面先用训练期间的故障事件做滚动回测；后续还需研究阈值与持续告警策略。留出测试结果已被查看，下一轮修改后不能再把同一测试区称为全新的独立验证。最终仍需不同场站、真实工单和维修结果作外部验证。

### 固定模型的告警阈值诊断

为确定误报能否仅靠提高阈值解决，保持首轮入选的 `transformer_seed2032` 及其分数不变，只用原验证集健康窗口的最大分数确定一个“验证集零健康窗口告警”阈值 **0.89550525**；它并不声称对未来数据有零误报保证。原宏平均 F1 阈值为 **0.05**。脚本 `src/evaluate_reunion_alarm_thresholds.py` 使用既有预测文件，在**已被查看过的**测试和正常压力区做回顾性诊断：

| 阈值 | 验证故障窗口检出 | 验证纯正常日告警 | 旧测试故障窗口检出 | 旧测试纯正常日告警 | 后续正常压力日告警 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 0.05 | 457/480 | 2/13 | 175/182 | 10/24 | 36/273 |
| 0.89550525 | 441/480 | 0/13 | 173/182 | 7/24 | 22/273 |

新阈值减少但没有消除跨日期误报，还损失 2 个旧测试故障窗口和 16 个验证故障窗口。旧测试与压力区已参与分析，**这不是一轮新的盲测，也不是生产阈值的验收结果**。单独调阈值无法达到期望的现场误报水平；需要更可靠的正常行为建模、事件级审核以及另一场站的已确认故障记录。

## 训练期滚动回测

为检验单一验证期可能造成的乐观估计，又只在原**训练分区**内做了两次时间前推回测。每折使用更早日期训练，中间日期选择候选模型与阈值，最后日期只评估所选模型；每折重新用其训练窗口拟合标准化，不读取原验证集、留出测试集或后续正常压力集。两折沿用同一批候选模型和三个种子。

| 回测 | 训练故障窗口 | 调参故障窗口 | 后续评估故障窗口 | 入选模型 | 后续故障召回 | 后续正常误报 |
| --- | ---: | ---: | ---: | --- | ---: | ---: |
| 2 月中旬：训练截至 2/9，调参 2/11–13，评估 2/14–18 | 77 | 54 | 294 | ExtraTrees | 289/294 | 16/249 |
| 3 月初：训练截至 2/18，调参 2/24–3/1，评估 3/9–11 | 425 | 59 | 280 | Transformer 三种子集成 | 276/280 | 0/26 |

第一折 16 个误报占正常窗口的 **6.4%**，说明即使事件召回率高，误报仍有实际影响。第二折评估期只有 **26 个正常窗口**、没有完整的无故障日期，因此 `0/26` 不能证明长期低误报。两个折的入选架构不同，也不足以断言某一个模型稳定最优。所有窗口以 5 分钟步长重叠，窗口计数并非独立样本数；实验均来自同一座电站，不构成跨电站验证。

回测代码和本地结果分别在 `src/backtest_reunion.py`、`reports/reunion_backtest_v1_mps/results.json`。复现命令：

```bash
PYTHONPATH=src python src/backtest_reunion.py --prepared data/processed/la_reunion_v1 --output reports/reunion_backtest_v1_mps --device mps --seeds 2031 2032 2033
```

这些回测仍不能修复前述留出测试的误报问题。下一轮需要按**事件和完整正常日期**共同设计调参目标，并寻找另一座带故障确认记录的电站作为外部评估数据。

第一折的 16 个误报窗口分布在 **2/14（8 个）、2/15（5 个）、2/18（3 个）**，不是单个瞬时尖峰。误报窗口最后一分钟的故障机/对照机功率比中位数为 **0.870**，直流电流比为 **0.848**；其余正常窗口分别为 **0.915 / 0.969**。这与真实遮挡造成的相对出力下降相似，单靠模型分数或简单持续时间规则难以辨别。保持原阈值、要求连续 2 个五分钟窗口才报警，第一折故障检出由 **289/294 降至 285/294**，误报仅由 **16/249 降至 15/249**；要求 3 个连续窗口则为 **281/294、14/249**。第二折没有误报可消除，却同样损失故障窗口召回。基于这两折，不采用这个简单的持续告警规则作为性能改进。

另用两折**当时已冻结的模型和阈值**检查各自调参期之后、原评估区遗漏的完整正常日期：第一折 2022-02-19—23 共 5 天/420 个正常窗口，第二折 2022-03-02—08 共 7 天/679 个正常窗口，两者都没有产生告警。脚本 `src/evaluate_reunion_backtest_normal_days.py` 只读取原训练分区和两折保存的模型；结果在本地 `reports/reunion_backtest_normal_days_v1.json`。这补足了回测正常日覆盖，但仍是同一场站的 12 天探索性检查，不能抵消正式留出测试区 **10/24 个正常日有告警**的结果，也不能把这些已查看日期当作下一轮盲测。

又针对误报尝试了在线困难正常样本加权：训练时只对模型当前认为像故障的**正常训练窗口**提高交叉熵权重；对照与实验使用相同多尺度 CNN、种子、折内标准化、调参日期和外层评估日期。`alpha=0/2/4` 在 A10G 上各跑 3 个种子、2 个训练期时间折。第一折外层平均 AP 为 **0.91305 / 0.91266 / 0.90792**，并没有改善；相应正常窗口误报数（按种子 2031/2032/2033）分别为 **3/14/15、4/14/17、4/14/18**，加权后还略增。第二折三组 AP 都为 1.0，但只有 **26 个正常窗口**，不能据此断言加权有利于实际误报。第一折无增益，因此暂不采用困难样本加权。代码为 `src/compare_reunion_hard_negatives.py`，完整日志与检查点在本地 `reports/reunion_hardneg_a10_v1/`。这属于探索性模型比较；在这些外层折上反复挑超参数，会削弱它们作为独立评估的可信度。

```bash
PYTHONPATH=src python src/compare_reunion_hard_negatives.py \
  --prepared data/processed/la_reunion_v1 \
  --output reports/reunion_hardneg_a10_v1 --device cuda \
  --seeds 2031 2032 2033 --alphas 0 2 4 --epochs 50 --patience 8
```

## 同站正常样本预训练：三种子对照

为了检验预训练是否真正帮助故障分类，先用**训练区的正常窗口**做随机时段和通道遮盖重建，再用同一训练区的有标签窗口微调多尺度 CNN；对照组用相同架构、相同种子、相同训练/验证区直接训练。两组都只根据验证 AP 早停，不读取既有留出测试区或正常压力区。A10G 上每组 3 个种子，预训练至多 20 轮，监督训练至多 50 轮。

| 种子 | 直接训练验证 AP | 预训练后微调验证 AP |
| --- | ---: | ---: |
| 2031 | 0.972613 | 0.971713 |
| 2032 | 0.968364 | 0.979226 |
| 2033 | 0.973592 | 0.973088 |
| 平均 | 0.971523 | 0.974676 |

平均值提高 **0.003153 AP**，但 3 个配对种子中只有 1 个提高，不能称为稳定增益。验证区只有同一场站的 5 个故障日期和 13 个纯正常日期，阈值也在同一个验证区选择，因此不能将其作为独立测试或工业效果证明。实验代码为 `src/compare_reunion_pretraining.py`；逐轮历史、检查点和逐种子指标在本地 `reports/reunion_ssl_a10_v1/`（大文件不提交 GitHub）。

```bash
PYTHONPATH=src python src/compare_reunion_pretraining.py \
  --prepared data/processed/la_reunion_v1 \
  --output reports/reunion_ssl_a10_v1 --device cuda \
  --seeds 2031 2032 2033 --pretrain-epochs 20 --epochs 50 --patience 8
```

## 气象增强：相同窗口的配对对照

原始气象流包含倾斜面辐照、直接辐照、环境温度和组件温度。为检验阴云与组件温度是否能解释部分误报，`prepare_reunion.py` 新增可选的 `--include-weather`：分块读取 2.24 GB CSV、按分钟取中位数、按同一分钟与电气流对齐；缺测分钟不构造窗口，标准化仍只在训练区拟合。分块边界的同一分钟会合并后再求中位数。用下载文件的首 100 万条完整记录检查，覆盖的 2021-10-28 至 11-09 区间内，日间对照逆变器发电分钟的气象匹配率为 100%。这是**局部对齐检查**，不能代表整段数据的覆盖率。

气象原始文件现已按发布方给出的文件大小和 MD5 `471c7408a65fcb304a3dc037ba2a5a24` 校验通过。完整预处理后，18 特征数据的训练/验证窗口分别为 **7,931 / 1,766**，其中故障窗口 **758 / 458**；相较于纯电气数据减少，主要因为气象流从 2021-10-28 开始，另有缺测分钟。预处理命令：

```bash
python3 src/prepare_reunion.py --raw-dir data/raw/la_reunion \
  --output data/processed/la_reunion_weather_v1 --include-weather
```

原 14 特征实验结果不会因可选开关改变。为了排除样本集合差异，对照实验统一读取新的 18 特征**训练/验证窗口**，一组只取前 14 个电气通道，另一组取全部 18 个通道；两组架构、种子、训练轮数和早停规则相同。已按窗口结束时间核对两版数据：训练 7,931、验证 1,766 个匹配窗口的标签完全一致，反标准化后的前 14 通道最大绝对差约 `6.1e-5`。A10G 上的结果：

| 种子 | 同窗口仅电气 AP | 同窗口电气＋气象 AP |
| --- | ---: | ---: |
| 2031 | 0.971259 | 0.965212 |
| 2032 | 0.968487 | 0.967063 |
| 2033 | 0.969869 | 0.968367 |
| 平均 | 0.969872 | 0.966880 |

简单拼接气象通道使平均验证 AP **下降 0.002991**，三个种子均未提高。13 个纯正常验证日期中，电气组各有 0 天告警；气象组对应为 2、0、0 天，但阈值就在同一验证区选择，这不是独立误报检验。由于气象组最佳轮数较早，又将双方学习率从 `8e-4` 同时降至 `2e-4` 重跑：电气组平均 **0.969113**、气象组平均 **0.968965**，差距缩至 **−0.000148**，但仍没有稳定增益（气象组仅 1/3 个种子提高）。不能声称气象信息无用，只能说明目前的同分钟拼接方式没有改善本任务。下一步可检查辐照和功率的物理归一化、跨传感器时间偏移，再在训练期滚动回测中比较。旧留出测试区已被查看，不再作为全新独立测试。

代码在 `src/compare_reunion_weather.py`，逐种子结果及检查点在本地 `reports/reunion_weather_a10_v1/` 和 `reports/reunion_weather_a10_lr2e4/`。复现命令：

```bash
PYTHONPATH=src python src/compare_reunion_weather.py \
  --prepared data/processed/la_reunion_weather_v1 \
  --output reports/reunion_weather_a10_v1 --device cuda \
  --seeds 2031 2032 2033 --epochs 50 --patience 8
# 第二轮使用新输出目录，并加 --lr 0.0002
```

### 时间对齐与物理派生特征检查

只从气象版**训练窗口**还原、去重得到 42,955 个分钟点，比较对照逆变器功率与 `GTI` 在 −10 至 +10 分钟的相关性。功率和辐照度的一分钟变化量在 **0 分钟偏移**时相关系数最高，为 **0.732**；原始量相关系数为 **0.983**。这支持当前同分钟合并，没有发现整分钟级的系统性错位，但相关性不能代替传感器时间戳校准。审计代码为 `src/audit_reunion_weather_alignment.py`，完整各偏移结果在本地 `reports/reunion_weather_alignment_v1.json`。

又在相同训练/验证窗口上尝试三个物理派生通道：故障机和对照机各自的功率除以 `GTI + 100`，以及组件温度减环境温度。派生通道**只用训练窗口**拟合均值和标准差。A10G 三种子验证 AP：原始 18 通道为 **0.965212 / 0.967063 / 0.968367**，加入派生通道后为 **0.962100 / 0.970103 / 0.967419**；平均 **0.966880 → 0.966541**。只有 1/3 个种子改善，因此也没有足够证据保留这些额外通道。代码为 `src/compare_reunion_physics.py`，完整结果在本地 `reports/reunion_physics_a10_v1/`。
