# 队友任务：数据库事件与短信、邮件通知

本文件是任务布置，尚未实现数据库、通知 Worker 或服务商发送。负责人待项目负责人分配，建议后端同学认领。项目负责人负责模型研发和 Agent 开发，不承担本模块。

## 功能目标

设备产生故障候选或人工确认故障后，通知相应设备负责人；每日实际发电量与当日预测值齐备后，通知全部启用的人员。**手机短信和邮箱邮件都要提醒**，两种渠道独立执行、独立留存结果。采用“数据库触发器 → 事务性通知事件/任务表 → Worker → 短信/邮件服务商 API”，触发器内不访问外网。

## 数据表与字段要求

这些是逻辑表，不要求分成三个独立数据库；数据库引擎由后端同学在技术方案中明确。沿用现有 SQLite 时按对应语法迁移，改 PostgreSQL/MySQL 时附带迁移和回退步骤。

| 表 | 最低字段/约束 |
|---|---|
| personnel | 员工 ID（主键）、姓名、手机、邮箱、是否启用、更新时间；手机和邮箱都需校验；联系方式缺失必须提示而非默默漏发 |
| equipment | 全局设备 ID（主键）或明确的电站+设备联合唯一键、电站 ID、名称、负责人 ID 外键；每台设备一个当前负责人、一人可负责多台；负责人变更可追溯 |
| equipment_observation | 设备+时间戳唯一，原始观测引用/JSON、数据质量；采用有时区的统一时间语义，避免重复采样覆盖 |
| model_result | 关联观测/设备/时刻、任务、模型 request_id、模型/阈值版本、原始结果、疑似类别、score、decision、质量状态；人工确认另外记录，不覆写模型原始结果 |
| daily_generation | 电站+当地日期唯一，实际发电量 kWh、预测发电量 kWh、预测生成时间/模型版本、业务时区、数据修订版本；值可空表示未就绪，0 是有效发电量 |
| notification_event | 事件 ID、业务去重键唯一、类型、设备/电站/日期、来源记录与版本、消息事实快照、创建时间；与触发的数据在同一事务落库 |
| notification_delivery | 事件 ID、收件人员 ID、渠道 sms/email、接收地址快照、状态、attempt_count、next_retry_at、provider_message_id、error_code、发送时间；唯一(event_id, recipient_id, channel) |

人员 1:N 设备关系通过 equipment 的负责人外键实现。联系方式变更后新事件使用新地址，已经发送的记录保留原地址快照用于审计；收件对象在事件展开时固定并留存。

## 触发与处理规则

1. **设备告警**：仅在进入新的异常事件/事件状态升级时生成通知事件，不是每条异常采样都发送。定义事件去重键与冷却时间；同一持续异常不会刷屏。模型 anomaly 是“疑似异常”，人工确认后才称“确认故障”。quality blocked、uncertain 或数据缺失不能发成确认故障短信。
2. **查负责人**：由事件关联设备查询启用负责人，生成短信、邮件两条 delivery。没有负责人或缺联系方式时记为待处理/失败并让管理界面可见，不能标成双通道成功。
3. **每日发电通知**：INSERT 和 UPDATE 都检查，实际与预测不论谁后到，二者齐备时均可触发。按电站+日期+数据修订版本去重，不能只在实际值 INSERT 时检查。迟到值或修订是否补发由明确策略决定，消息注明修订；重复写入相同版本不重复发。
4. **时序模型限制**：当前已开发时序模型是运行异常检测，尚没有每日发电量预测服务。先完成 daily_generation 的存储及“双值就绪”触发逻辑，用明确标注的测试值验收；不能把异常分数当预测电量，不能宣称预测接口已完成。真实预测值由未来发电量模型提供。
5. **群发范围**：每名启用员工分别生成 sms、email 两条任务；邮件逐个发送或用合适的批量 API，不能把全体员工邮箱暴露在 To/CC。
6. **Worker**：原子领取任务，有限并发、超时、指数退避、最大重试和失败待人工处理状态；进程崩溃后能恢复超时租约。成功渠道不因另一渠道失败而重发。
7. **幂等性**：数据库唯一约束防重复展开；有服务商幂等键则使用；出现“服务商已接收但本地未记账”的超时，先核验发送状态再重试，不能承诺数据库本身保证外部短信严格只发一次。
8. **测试与真实发送**：默认 mock/dry-run，记录模拟发送且界面明确标识；接入真实号码/邮箱并发出测试消息须有明确授权。服务商密钥只放服务器配置，日志脱敏，不进 Git。

## 必须跑通的测试

- 一人两台设备：设备 A 异常仅通知其负责人；另一负责人不收到。
- 同一事件重复写入/重复执行 Worker：每个员工每渠道只生成一条业务 delivery，不因重复采样再创建告警。
- 短信失败、邮件成功：只重试短信；反过来也成立；界面显示部分成功。
- 实际先到、预测后到，以及预测先到、实际后到：各自只生成该版本的一轮双通道通知；0 kWh 正常触发。
- 事务回滚不发送；Worker 中断后可恢复；服务商超时留有待核验状态。
- 未启用员工不群发；无负责人、空手机号、非法邮箱有可定位的错误记录。
- uncertain/blocked 不被写成“已确认故障”；测试预测值始终注明模拟。

比赛两天内优先 N1–N6 的 mock 闭环和 N7 基础页面；真实短信签名/模板、邮箱服务商账号由团队提供并在具备授权后接入。本模块不要求负责人暂停模型与 Agent 研发来代做。
