# 智能体会话、历史查询与证据问答

关联 Issue #8。此版本保留原设备分析、异步任务和草稿接口，增加独立会话与普通问答。

## 用户可见行为

- “列出之前的设备分析记录”查询当前身份有权读取的分析，最多最近 20 条；“刚才是否分析过该设备”限定当前会话，不重新执行诊断或请求模型。
- “为什么这样判断”引用当前会话保存的观测。深入追问可使用模型，但不开放设备工具、不重新运行完整设备分析；没有上下文时先说明缺少引用对象。
- 纠错作为 `user_feedback` 保存，`verified=false`；可以修正后续提问对象，不能覆盖设备观测或直接形成确认故障。
- “新会话”生成新的会话 UUID、清空当前上下文；重复分析同一设备会生成新的分析记录。历史会话可打开并在刷新后恢复。
- 前端提供自动选择、直接问答、完整诊断三种展示方式。普通问答先回答问题，按需展开事实；完整报告只显示一套事实、未排序可能性、核查清单和未知信息。
- 复合问题拆为至多 8 项，每项均返回答案或明确的证据不足/未接入状态。`coverage` 记录覆盖情况，不能将数据缺口当成功查询。

## 身份与隔离

| 标识 | 来源 | 用途 |
| --- | --- | --- |
| 用户归属 owner | 配置认证的账号 ID；或浏览器访客随机标识 | 服务端记录访问控制，不信任客户端自报账号/角色 |
| `X-Fumai-Client` | localStorage 的随机 UUID，仅用于匿名演示 | 同一浏览器的标签页可查看自己的访客历史；不同浏览器不是同一账号 |
| `X-Fumai-Session` | 标签页会话 UUID | 指定当前上下文；新会话、新标签页生成新值，刷新保持 |
| run_id | 服务端生成 UUID | 一次回答/分析的审计编号 |
| task_id / request_id | 服务端任务 UUID / 客户端幂等请求 UUID | 异步进度及重试；不能用问题文本去重替代新会话分析 |

已有 `AGENT_USERS_JSON` 配置账号继续使用个人 Bearer 令牌；同一已认证账号跨浏览器归属相同，聊天会话仍独立。认证需经 HTTPS；Nginx 应覆盖而非透传客户端的 `X-Forwarded-Proto`。前端令牌仅存当前标签页 sessionStorage，退出时清除。当前网站如果仍是 HTTP 访客演示，不宣称已经提供跨浏览器登录：须由团队的认证部署配置个人账号后使用。

访客 UUID 是访问其演示历史的随机能力标识，不是实名用户 ID。公共设备事件、共享人工复核和联系人数据应由业务认证系统及数据库提供，不向所有访客共享私人聊天。没有持久存储权限时退回原有会话级访客行为，不伪称跨标签已同步。

## 只追加迁移与旧数据

新增 `conversations`、`run_context`、`run_devices`、`legacy_access` 表与索引，保持原 runs 五列、答案 JSON、草稿和确认人不变。旧记录创建派生索引并归入原会话，迁移幂等。携带原随机会话标识的访客可领取该会话的历史访问别名，不合并其他访客的记录。查询 run、task、conversation、draft 都检查用户归属。

发布前用 SQLite backup API 备份审计库；代码失败回退时保留数据。旧版程序的五列 INSERT 保持可用。旧 UI 不理解新的 `answer` 响应类型，因此前后端应作为同一版本发布，客户端发布后刷新。回退不会自动删除新会话或新审计记录。

## 新增接口与字段

所有请求保留 Origin 检查、原认证方式和会话隔离。匿名演示附带两个 UUID 请求头；认证账号仍由服务器配置映射 owner。

| 接口 | 作用 |
| --- | --- |
| GET `/agent-api/bootstrap` | 新增 identity、conversation_id、当前 turns、会话列表和 capability 状态 |
| POST `/agent-api/history` | 只读分析列表；可选 device_id、conversation_only、limit 1–100、offset 0–10000 |
| GET `/agent-api/conversations` | 当前身份的最近 30 个已保存会话 |
| POST `/agent-api/conversations` | `{conversation_id}`：验证归属后读取至多最近 20 轮 |
| POST `/agent-api/analyze`、`analysis-tasks` | 新增 response_mode：auto / chat / report；原字段与幂等行为保留 |

回答类型：`direct` 为身份/帮助等固定说明；`answer` 为历史、知识、上下文、纠错和业务数据查询；`analysis` 为新设备分析。新回答含 `answers[]`，每项提供 question_id、question、intent、status、answer、evidence_ids。未知业务状态使用 `not_connected`，证据不足使用 `insufficient`。用于草稿的结果必须仍为 analysis。

上下文仅在当前会话内读取最近 16 轮，并保留可定位的最近分析；发给模型的历史最多 8 轮且截断文本。历史用户输入和纠错均标为不可信说明，模型不得据此增加权限或改写观测。

## 证据约束

`facts` 给出事件、设备、数值字段与引用来源。功率/同群观测不直接证明通信异常或采样缺失；目前快照没有通信日志和逐点缺失明细。模型输出出现无依据的原因排名、肯定的缺失/通信原因或与观测字段不符的带单位数字时，丢弃模型解释并保留规则事实；不能用修改提示词代替服务端校验。

显式设备范围会限制模型工具结果；上下文问答禁用设备工具。模型输出经过结构、引用、问题编号和数值/原因规则校验，但这不构成通用自然语言事实验证器。场景扩展应补充对应的事实字段和独立评测，不宣称任意推理都已经正确。

## 后续业务接入边界

| 能力 | 本次状态 | 后续依赖 |
| --- | --- | --- |
| 自然语言个人分析历史 | 已实现 | 当前智能体审计库 |
| 上下文追问、纠错、会话恢复 | 已实现 | 当前会话与版本化快照 |
| 设备功率/同群观测 | 读取快照，保留样例/实测标记 | 实时数据适配及质量信息 |
| 当前设备状态、负责人 | 明确提示尚未接入本智能体 | 业务设备表、认证和字段映射 |
| 复核进度 | 仅可解释所引用快照中的状态 | 共享业务复核 API，不冒充实时进度 |
| 实际/预测发电量及偏差 | 明确未接入 | 真实电量与发电量预测服务；异常分数不是预测电量 |
| 短信与邮件投递状态 | 明确未接入 | 队友通知模块的发布、授权和只读适配；mock 与真实发送分开 |
| 电站日报、运维总结 | 不生成缺少数据的运行日报 | 完整日运行、告警、发电量和人工复核数据 |

业务同学已经提交 notifications 模块；本次没有接管其服务、修改其数据库或发出通知。可在冻结身份与数据映射后，将它的只读结果加入统一查询计划。当前 capability=false 表示“尚未接入本智能体”，不据此断言队友没有代码。

## 验证

```bash
python -m unittest discover -s agent/tests -q
node frontend/tests/agent-task.test.mjs
node frontend/tests/intent.test.mjs
```

真实浏览器回归使用 `frontend/tests/conversations.browser.cjs`：先用临时数据库启动本地 demo 服务，`--static-root frontend/dist`，设置 `AGENT_ORIGIN` 与 URL 一致；不配置模型密钥。设置 FUMAI_CHECK_URL、FUMAI_PLAYWRIGHT_MODULE、FUMAI_BROWSER_EXECUTABLE 和 FUMAI_TEST_OUTPUT 后执行 Node 脚本。覆盖历史不重跑、纠错、多问题、新会话、跨标签、刷新、不同访客隔离和手机输入栏。
