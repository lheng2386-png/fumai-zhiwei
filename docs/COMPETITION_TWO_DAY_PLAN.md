# 两天比赛版交付：三个模型与证据协同

目标按用户要求调整为大学生比赛可演示原型。两天是交付约束，不是两天实现工业验收或超过 SOTA 的承诺。模型、数据处理和 Agent/云边端接口由项目负责人负责；队友继续前后端开发，此计划不替代他们的工作。

## 演示要交付什么

1. 时序故障诊断、组件热像分类、整图缺陷检测各有固定权重、输入样例和可运行推理命令。
2. 输出可交给队友接入：设备、时间、模型版本、分数/阈值来源、类别/框/时序异常、输入质量状态。
3. 从模型结果形成有依据的复核优先级，展示证据不足、单源异常、双证据支持及证据冲突。
4. 有效果表、局限说明、离线备用样例和演示操作顺序。训练权重另行交付，不用提交 Git 大文件。

已有模型与系统贡献分开说明：骨干使用现有开源架构并在光伏数据上训练；本项目的工作包括数据清洗/隔离、配对实验、质量处理、证据协同和运维交互。不能把换骨干或拼模块说成新发明。

## 两天安排与验收

| 时间段 | 任务 | 可核验输出 |
| --- | --- | --- |
| 第一天前半 | 收尾当前 GRU/检测试验，锁定比赛权重；不再开泛化搜索或大规模新预训练 | 三模型清单、权重哈希、评估依据 |
| 第一天后半 | 补统一推理和数据质量输出，完成协同接口；让队友用固定 JSON 调试 | 三条真实推理结果、接口说明、失败输入测试 |
| 第二天前半 | 与现有前后端联调，接告警解释、结果展示和人工复核入口 | 从输入到复核的完整演示流程 |
| 第二天后半 | 逐场景彩排，整理对比表、创新说明和离线备用结果 | 启动说明、演示样例、答辩证据 |

这是执行计划，尚未完成的接口或联调不能在答辩材料中标为已交付。云服务断开时优先用本机已备份权重做推理和离线演示；新训练不阻塞演示链路。依赖队友的前后端联调进度需同步核实。

## 可展示的系统设计点

### 1. 输入质量先于诊断

已有时序质量门控保留缺测来源，遇到时间间断、低对照功率或缺测时明确拒判。比赛版图像入口还需完成模糊/异常输入检查；当前不能声称这一部分已接好。不能用均值填充后把未知当健康。

### 2. 同设备、近同时的双证据协同

新增 `src/competition_evidence.py`，保留原模型分数，不把时序 softmax、分类 softmax 与检测置信度直接平均成“故障概率”。三个模型的原始输出由适配器按各自固定规则形成 `normal/anomaly/uncertain`，策略层只形成复核建议。

- exact `plant_id + asset_id` 匹配。组件与逆变器的归属应由前后端资产表显式确认，模型不猜设备映射。
- 时间必须有时区；相对于 `as_of` 排除未来、过期和输入质量不合格记录。默认最长有效 30 分钟、证据间隔 15 分钟，是演示配置，非学习所得最优参数。
- 每个任务只用最新记录，避免旧预测累计投票；同任务同时间多个记录有歧义时拒绝。
- 分类与检测都是视觉模态，同一照片不能算“两份独立证据”。时序和视觉还必须有不同 `observation_id` 才能形成跨模态支持。
- 支持与正常证据冲突 → 高优先级人工复核；只有不确定/缺失 → 数据检查；只有单模态异常 → 普通异常复核；时序与视觉共同异常 → 高优先级复核。
- 没有自动控制设备、自动维修、故障因果确认或新概率输出。

当前是固定规则策略与可运行组件，不是端到端多模态训练模型，也不是已经证实的新颖算法。应将其作为本项目可解释协同诊断设计，在答辩中通过对照场景展示价值。

### 3. 决策可追溯

每条证据携带 `model_version`、`threshold_version`、原观测 ID 与 `data_kind`。输出保留原证据、采用/排除原因、策略版本和输入 SHA-256；人工复核持久化沿用/对接现有 review 模块，尚不能把本模块说成完整工单系统。

## 给队友的接口

输入是证据对象列表，样例在 `examples/competition/`。每条必须包含：

| 字段 | 含义 |
| --- | --- |
| evidence_id | 唯一证据 ID，重复即拒绝 |
| plant_id / asset_id | 已由系统确认的场站和资产 |
| observed_at | 原观测时间，ISO 格式并含时区；不能用推理运行时间冒充采集时间 |
| task | timeseries / classification / detection |
| observation_id | 原采样窗口或原始图像 ID，分类/检测同图共用此值 |
| model_version / threshold_version | 使用的权重和阈值策略版本 |
| quality | ready / blocked；blocked 必须有 quality_reason |
| decision | anomaly / normal / uncertain |
| data_kind | public_research / site_observation / synthetic_demo |
| score（可选） | 原模型有限 0–1 分数；不参与跨任务平均 |

检测没有框不能直接适配为“确定健康”，应按任务覆盖和输入质量返回 uncertain；分类模型只能在其十类定义下给判断，不应将类别映射成未经训练的新故障。适配器尚需和三条真实推理入口联调。

输出的 `status` 为 `insufficient_evidence / normal_observed / single_source_review / conflict_review / corroborated_review`；展示 `reason`、`excluded` 与 `supporting_evidence_ids`。`normal_observed` 只代表已观测范围，页面文案建议“当前证据未提示异常”。`automatic_control_action` 始终为空。

## 现在可运行的协同演示

```bash
bash scripts/demo_competition_evidence.sh reports/competition_demo_new_run
python3 -m unittest discover -s tests -p 'test_competition_evidence.py'
```

脚本已经真实运行：双证据支持、冲突、质量阻断、同视觉模态、不同资产五个场景均有输出；6 项测试覆盖身份/时间/质量拒绝、旧证据替代、顺序不变及无效概率等。不会覆盖既有输出目录中的 JSON。

**这五个例子都是明确标记的模拟业务关联**，输出含 `demo_only=true`。现有时序、分类和检测公开数据不是同设备同时刻的配对采集，不能篡改资产 ID 拼成真实联合验证。各模型的真实推理演示与联合流程模拟应在页面和答辩中分开标注。
