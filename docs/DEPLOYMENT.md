# 每次小步交付后的推送与部署

负责人：STIAN45663。关联任务：#2。此约定来自项目成员要求：每完成一项可验收的小改动，验证、推送 GitHub，并部署到团队服务器。

## 固定顺序

1. 在自己的开发分支完成一个可运行的小改动，执行相关检查。
2. 检查差异、提交并推送 GitHub，取得完整提交 SHA。个人分支直接提交；合入 `main` 时仍通过 PR。
3. 以该 SHA 部署对应组件。不能把未提交的本机代码直接覆盖线上。
4. 检查 HTTP、版本标记及该改动涉及的交互或接口；不把“进程启动”当作部署完成。
5. 向队友交接提交号、检查结果、访问入口和已知限制。失败时恢复上一版，再排查。

这个流程由执行开发的人在每次小步交付后运行；没有安装定时拉取、无人值守轮询或跨分支自动合并任务。

## 前端部署

前端为静态资源，由 Nginx 提供服务。服务器只需要 Python 3 和 Nginx，不需要运行 Node.js 构建服务。

```text
/srv/fumai-zhiwei/frontend/
├── releases/<完整提交 SHA>/dist/
├── current -> releases/<当前 SHA>
├── previous -> releases/<上一 SHA>
├── .deploy.lock
└── deployment-history.jsonl
```

部署脚本为 `ops/deploy_frontend.py`；首次 Nginx 配置参考 `ops/nginx/fumai-zhiwei.conf`。先检查服务器已有服务和 80 端口，不覆盖队友的站点配置。连接信息使用团队私下提供的 SSH 别名 `fumai-demo`，仓库不记录真实连接地址、密码或私钥。

首次安装脚本后，对已推送到 GitHub 的版本执行：

```bash
ssh fumai-demo 'python3 /srv/fumai-zhiwei/ops/deploy_frontend.py --commit FULL_COMMIT_SHA'
```

将 `FULL_COMMIT_SHA` 替换为真实的 40 位提交号。脚本从指定的公开 GitHub 提交下载源归档，只提取 `frontend/dist/` 的普通文件，不执行仓库中的安装或构建脚本。它拒绝路径穿越、链接、重复文件及超出体积限制的归档，使用文件锁串行发布，原子切换 `current`，核对 HTTP 提交标记和静态文件，失败时回退。旧发布目录不自动删除。

核对版本：

```bash
ssh fumai-demo 'curl -fsS http://127.0.0.1/deployment.json'
```

也应从自己的浏览器检查团队提供的公网访问地址。服务器本机成功而公网失败时，核对云安全组和入站 TCP 80；不要因此反复重装服务。

回退到一个已存在的历史提交：

```bash
ssh fumai-demo 'python3 /srv/fumai-zhiwei/ops/deploy_frontend.py --commit PREVIOUS_FULL_COMMIT_SHA'
```

部署脚本的边界与回退测试在 Linux 上运行：

```bash
python3 -m unittest discover -s ops/tests -p 'test_*.py' -v
```

覆盖正常发布保留旧版本、健康检查失败回退、不覆盖真实目录、归档路径穿越及链接拒绝；测试使用临时目录且不访问网络。

前端页面、演示数据或样式变更后，仍需完成桌面/手机检查。服务器域名与 Sites 预览的浏览器存储相互独立，模拟复核草稿不会自动同步。

## 后端接入与部署约定

当前仓库还没有已部署的 HTTP 后端。Nginx 的 `/api/` 暂时明确返回 503 `not_connected`，不能当作业务接口已完成。

后端成员在首次接入时，确定分支、服务入口、Python 环境、端口、数据库路径及健康检查。建议服务仅监听 `127.0.0.1:8000`，由 Nginx 统一代理 `/api/`；启用代理前必须协调接口路径是否保留 `/api/` 前缀。数据、权重、数据库和配置分别放在独立目录，部署不能覆盖这些持久化产物。

后续每次后端交付同样先测试和推送，再按提交号部署、重启自身服务、验证健康检查与真实接口；失败时恢复代码和服务。数据库迁移需有独立备份与兼容方案，不套用静态前端的软链接回退。

暂不替队友选择和部署未知的后端分支，也不关闭或重启其他成员的进程。

## 凭据与共享服务器

- 密码、私钥、令牌不写入 Git、Issue、截图或部署日志。
- 本轮通过 SSH 的隐藏密码提示完成登录；仓库脚本本身不处理或保存密码。
- Nginx 和发布根目录已就绪后，更新静态文件只需切换发布版本，不必每次重启整个服务器。
- 保留可回退版本和验收记录；需要调整共同入口时先协调其他组件的占用。
