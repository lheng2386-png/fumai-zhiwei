# PVF-10 高分辨率红外分类：修复划分与首轮模型比较

[PVF-10 发布仓库](https://github.com/wangbobby1026/PVF-Dataset)包含 5,579 张组件裁图，原始 TIFF、110×60 和 112×112 PNG 是同一批裁图的三种表示，不是三倍独立样本。本实验只使用 112×112 RGB PNG。ZIP 已通过 CRC，归档 SHA-256 为 `5bbedd95fd99b98198fcea84017c9243af8d4e8aeef307a3bd77200919195189`。这是**组件裁图十类分类**，不能用来计算整图缺陷检测 mAP。

## 为什么不能沿用发布包的训练/测试目录

发布包训练和测试文件夹的数字前缀对应不同语义类别。例如训练文件夹 `09substring open circuit`，测试文件夹却是 `01substring open circuit`；按数字或文件夹顺序映射标签会错标。`src/prepare_pvf10.py` 按去掉两位数字后的类别名称建立统一映射。

文件名中可解析出原始 DJI 照片标识和拍摄日期。在 112×112 版本中，**378 个原始照片组**同时出现在发布的训练和测试目录；112×112 与 110×60 两个版本之间，同名裁图的发布训练/测试归属还有 **994 张不一致**。这些事实使原目录不适合独立泛化评估。无法从归档核实八座电站各自的照片 ID，因此也不能声称已经做了跨电站划分。

我们按**拍摄日期**重新隔离：训练 2,805 张（14 天）、验证 1,085 张（2023-02-23、2023-04-07）、暂留测试 1,689 张（2023-11-14、2023-11-21）。三部分均有十类，日期和原始照片组不重叠；新划分中没有跨部分的解码像素完全重复。日期是比随机裁图更严格的代理分组，但仍不等于航次或电站独立。测试日期根据类别覆盖选定，不能描述成完全未参与任何设计的外部盲测。原图和新划分文件只留本地，不上传 GitHub。发布仓库没有单独明确的数据商业使用许可，当前只用于研究。

## 第一轮验证集结果

相同新划分、相同 112×112 输入，比较自主残差 CNN（随机初始化）与公开 ImageNet 权重的 ResNet18。两者在本机 Apple MPS 完成训练，按日期隔离的验证集宏平均 F1 早停；模型选择只读取训练/验证文件，**留出测试文件未读取**。
ResNet18 使用 torchvision `IMAGENET1K_V1` 权重，下载文件 SHA-256 为 `f37072fd47e89c5e827621c5baffa7500819f7896bbacec160b1a16c560e07ec`。

| 模型 | 种子 | 验证宏平均 F1 | 最佳轮次 |
| --- | ---: | ---: | ---: |
| 自主残差 CNN | 2026 | 0.4217 | 26 |
| ImageNet ResNet18 | 2026 | 0.5371 | 7 |
| ImageNet ResNet18 | 2027 | **0.5724** | 18 |
| ImageNet ResNet18 | 2028 | 0.4967 | 12 |
| ResNet18 三种子等权平均 | — | 0.5308 | 各自最佳 |

按照预先固定的“最强单模型对比三种子等权集成”规则，选中 **ResNet18 种子 2027**；三种子集成没有增益。三种子单模型均优于自主 CNN，但从 0.497 到 0.572 的波动明显。2027 模型对 `healthy panel` 和 `hot cell` 的 F1 分别为 0.863、0.801；`short circuit panel` 只有 **0.188**（验证 12 张），`string short circuit` 为 **0.372**（30 张），`junction box heat` 为 **0.381**（9 张）。这些少数类和跨日期变化仍阻止生产使用。论文在其划分上的总体准确率与我们的日期隔离宏 F1 不是同一指标，不能直接对比或宣称超过论文方法。

同一日期划分、种子 2027 和训练设置下，另用 torchvision 的 ImageNet **EfficientNet-B0** 权重做了一次骨干网络对照。25 轮（约 165 秒）中，最高验证宏 F1 为 **0.4454**，明显低于配对 ResNet18 的 **0.5724**；因此不继续为这个设置增加随机种子，也不替换当前入选模型。该结果只排除本次输入分辨率与超参数组合，不能断言 EfficientNet 在其他训练策略下普遍较差。实验结果在本地 `reports/pvf10_efficientnet_b0_mps_seed2027_v1/`，测试日期仍未读取。

结果和权重保存在本地 `reports/pvf10_date_mps_seed2026_v1/`、`reports/pvf10_resnet18_mps_seed202{6,7,8}_v1/` 和 `reports/pvf10_date_selection_v1.json`。约 102 秒的自主 CNN 训练、42/77/57 秒的 ResNet18 训练不包含数据整理和人工审计；这些时间只是本机 MPS 实测，不是服务器训练估时。

```bash
python3 src/prepare_pvf10.py
PYTHONPATH=src python3 src/train_pvf10.py \
  --output reports/pvf10_date_mps_seed2026_v1 --device mps
for seed in 2026 2027 2028; do
  PYTHONPATH=src python3 src/train_pvf10_transfer.py \
    --output reports/pvf10_resnet18_mps_seed${seed}_v1 --device mps --seed "$seed"
done
PYTHONPATH=src python3 src/select_pvf10.py \
  --runs reports/pvf10_resnet18_mps_seed2026_v1 \
         reports/pvf10_resnet18_mps_seed2027_v1 \
         reports/pvf10_resnet18_mps_seed2028_v1 \
  --baseline reports/pvf10_date_mps_seed2026_v1 \
  --output reports/pvf10_date_selection_v1.json
```

下一步应针对少数类和跨日期成像变化做有控制的增强、预训练骨干比较，并用新航次/新电站的确认标签检验。不能把已有 sUAS 单正射影像或当前 PVF-10 日期验证集重复调参后的分数当作工业性能。

## ConvNeXt-Tiny 三种子配对对照（2026-10-20）

在同一日期划分、112×112 输入、ImageNet 预训练、最多 25 轮、早停耐心 6、batch 64、骨干学习率 `2e-5`、分类头学习率 `3e-4` 下，补齐 ConvNeXt-Tiny 三种子。增强和类别权重沿用 ResNet18 设置；该骨干仍是卷积网络。按验证宏 F1 选轮次，未读取暂留测试 NPZ。

| 种子 | ResNet18 验证宏 F1 | ConvNeXt-Tiny 验证宏 F1 | 差值 |
| --- | ---: | ---: | ---: |
| 2026 | 0.5371 | 0.6096 | +0.0725 |
| 2027 | 0.5724 | 0.6095 | +0.0371 |
| 2028 | 0.4967 | 0.5946 | +0.0979 |
| 三个单模型均值 | 0.5354 | **0.6046** | **+0.0692** |

三个配对种子均改善；这是当前日期验证区上比此前换用 EfficientNet 更有价值的骨干调整。ConvNeXt 三种子平均概率集成宏 F1 为 **0.6035**，没有超过种子 2026 的 **0.6096**，按既定规则暂选后者。三次本机 MPS 训练分别耗时 **217 / 229 / 282 秒**，不含数据准备；当前样本量不需要大显存服务器才能开展这类微调。

所选模型健康类 F1 **0.9184**，但 366 张健康裁图中仍有 **34 张**被分到缺陷类；`bottom dirt` 召回仅 **17/83**，`junction box heat` F1 **0.3200**，`short circuit panel` F1 **0.2326**。均值提高没有消除少数类失效和误报，也没有验证跨电站能力。该验证区只有两天且被反复用于开发，因此这是研究阶段的候选更新，不能作为生产验收或 SOTA 结论。

结果在本地 `reports/pvf10_convnext_tiny_mps_seed202{6,7,8}_v1/` 和 `reports/pvf10_convnext_date_selection_v1.json`；权重不提交 Git。复现训练时，把前面的 `train_pvf10_transfer.py` 命令加上 `--architecture convnext_tiny`，种子保持 `2026 2027 2028`；选型仍用 `select_pvf10.py`，传入这三个新目录。

### A10G 并行输入尺度实验

在 D-FINE 训练的同时，另启动 ConvNeXt-Tiny 的 **112 / 224 输入配对实验**。两个尺度在同一 A10G 上依次训练，固定种子 2027、batch 64、学习率、增强、最大轮次和早停设置，避免直接把 MPS 与 CUDA 的差异算作尺度增益。只上传训练和验证 NPZ；数据、预训练权重及脚本 SHA-256 在两端核对，记录于服务器 `reports/pvf10_scale_a10_v1_manifest.json`。

`train_pvf10_transfer.py --input-size 224` 在每个 batch 内先做双线性插值再按 ImageNet 均值方差标准化；源裁图仍为 112×112。这检验预训练骨干对输入尺度的适应，插值不会增加真实热像细节。原默认值仍是 112。实验目录为 `reports/pvf10_scale_a10_v1/input112/`、`input224/`，各有独立日志、最佳权重和验证概率；启动不代表已取得性能增益，需在两组完成后对比指标及并行运行成本。

两组现已完成，结果如下；均只读取相同日期验证区：

| 输入尺度，种子 2027 | 验证宏 F1 | 健康裁图误判为缺陷 | 最佳轮次 | 实际训练耗时（与 D-FINE 并行） |
| --- | ---: | ---: | ---: | ---: |
| 112×112 | 0.6061 | 44/366 | 12 | 110 秒 |
| 224×224 | **0.6421** | **31/366** | 16 | 359 秒 |

宏 F1 提高 **0.0360**，健康误判减少，但并非每类都改善：`bottom dirt` F1 从 **0.3276 降至 0.2292**；`junction box heat` 从 **0.3077 提高至 0.4167**。这是一个配对种子，下一步仍需其他种子验证，不能和前面的三种子容量比较混成稳定性结论。结果与验证概率已取回本机，源裁图和暂留测试保持原协议。

D-FINE 完成后，继续安排种子 **2026、2028** 的 112/224 配对训练，每组沿用相同超参数与日期划分，分别保存到 `reports/pvf10_scale_a10_v1/input{112,224}_seed{2026,2028}/`。这些补充训练完成之前，224 的增益仍只由一个种子支持。


### A10G 三种子尺度对照完成

上述四组补充实验已全部完成；与种子 2027 合并后，同一 CUDA 环境、相同日期划分的结果如下。仍未读取暂留测试集。

| 种子 | 112 输入宏 F1 | 224 输入宏 F1 | 差值 |
| --- | ---: | ---: | ---: |
| 2026 | 0.6188 | 0.6604 | +0.0416 |
| 2027 | 0.6061 | 0.6421 | +0.0360 |
| 2028 | 0.6069 | 0.6522 | +0.0453 |
| 单模型均值 | 0.6106 | **0.6515** | **+0.0410** |

三组均改善，支持后续以 224 输入作为当前候选配置。112 三种子等权概率集成宏 F1 为 0.6312；224 集成为 0.6490，低于 224 种子 2026 单模型的 **0.6604**，因此按验证宏 F1 暂选该单模型。其健康误判为缺陷 **30/366**；224 集成为 **27/366**，说明误报与整体类别平衡指标存在取舍，不能只凭最高宏 F1 判断工业适用性。

补充训练实际耗时：种子 2026 的 112/224 分别约 81/174 秒，种子 2028 约 80/213 秒。训练已结束，服务器 GPU 当前空闲。结果、验证概率及所选单模型权重已备份到本机 reports；原始 112 裁图插值到 224 不会增加实测热像信息。当前验证区已经反复用于开发，跨电站验证、少数类与误报仍需改进，不能据此宣称达到生产验收或 SOTA。
