# SolarMagix 多场站时序预训练

目标是先用真实多场站运行序列训练一个可复用的时序编码器，再研究如何迁移到带确认故障标签的数据。这里的指标是**遮挡输入重建误差**，不是故障识别率。

数据来自 [Mendeley Data v2](https://doi.org/10.17632/4zgsckxpdy.2)（CC BY 4.0）。当前已下载并验证 SHA-256 的小时级逆变器、电站、设备和状态映射文件。文件不随 Git 仓库分发；可在本机或服务器复现下载，本地清单和数据审计在 `data/raw/solarmagix/`。

## 数据处理

小时级逆变器表含 112,249 行、50 台逆变器、7 个电站。记录主要覆盖白天，最长连续片段只有 21 小时，因此不能直接用 24 小时连续窗口。预处理使用**同一设备的连续 8 小时窗口**，步长 4 小时；隔夜和缺测处断开。剔除状态为 ERROR、非有限值、负功率和效率超过 110% 的行。保留交流/直流功率、设备/环境温度、短波与倾斜面辐照 6 个输入。异常的 `shortwave_radiation_instant` 和由功率计算的效率不作为特征。

训练区 5 个电站、31 台逆变器；验证区 1 个电站、8 台逆变器；留出测试区 1 个电站、11 台逆变器。截断上下分位数、中位数和 IQR **只在训练区拟合**。当前生成 12,169 / 1,932 / 2,743 个训练/验证/测试窗口。留出测试电站 `b596…` 尚未用于模型选择。前期在另一电站 `e2afd…` 做过 3 轮本机流程检查，其误差不能当作新独立测试，也不应据此选模型。

```bash
python3 src/fetch_solarmagix.py
python3 src/audit_solarmagix.py
python3 src/prepare_solarmagix.py
python3 -m unittest tests.test_solarmagix -v
```

## 模型与运行

`pretrain_solarmagix.py` 使用项目自研的多尺度时序 CNN：并行 3/7/15 卷积核提取不同时间尺度，随机遮挡连续两小时及部分传感器通道，只在遮挡位置计算重建损失。验证电站决定最佳轮次；之后才读取留出电站一次。默认宽度 64、深度 3、最多 30 轮、早停耐心 6 轮。

在带 PyTorch CUDA 的 A10 环境中，从仓库根目录运行：

```bash
python3 -c 'import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))'
python3 src/fetch_solarmagix.py
python3 src/prepare_solarmagix.py
python3 src/pretrain_solarmagix.py --data data/processed/solarmagix_8h.npz --output reports/solarmagix_ssl_a10_v1 --device cuda --batch-size 256
```

如果显存不足，改用 `--batch-size 128`；若仍不足，依次减小 `--width`，并记录不同配置。输出的 `best.pt` 含编码器、特征顺序和训练区归一化参数，`results.json` 含验证与留出电站误差、零填充基线、训练轮次及数据文件哈希。只克隆 Git 仓库不足以复现，须先执行下载命令或上传已校验的原始 CSV。

本机 Apple GPU 上，宽度 32/深度 2 的 3 轮**流程检查**用约 6 秒训练；不能据此推断 A10 的实际时长或完整实验效果。实际 A10 用时以服务器日志为准。迁移到 La Réunion 故障模型还需要特征适配器和严格的验证协议，不能直接把重建误差当作故障性能提升。

## A10G 第一轮结果（2026-10-18）

在 **NVIDIA A10G 24 GB**、PyTorch 2.8.0+cu128 上按上述默认配置训练，模型有 **126,444 个参数**，30 轮约 **17 秒**，第 25 轮验证误差最低。原始 8 个文件在服务器重新通过 SHA-256 校验，服务器数据切分与本机一致；检查点 `reports/solarmagix_ssl_a10_v1/best.pt` 已从实例取回本机保存。GPU 训练输出保存在本地忽略目录 `reports/solarmagix_ssl_a10_v1/`，未把权重提交到 Git。

| 遮挡输入重建 MSE（归一化尺度） | 验证电站 | 留出电站 |
| --- | ---: | ---: |
| 零填充 | 0.2780 | 0.2679 |
| 时间线性插值 | 0.1431 | 0.1439 |
| 自研多尺度 CNN | **0.0275** | **0.0260** |

线性插值基线在整条传感器通道被遮挡时只能回退为零，因此这个比较考察了跨传感器重建能力，不能外推为故障分类优势。留出电站分数在本轮已经读取，后续改模型时不能继续称同一电站为全新独立测试。复现插值基线：

```bash
python3 src/compare_solarmagix_baselines.py \
  --data data/processed/solarmagix_8h.npz \
  --results reports/solarmagix_ssl_a10_v1/results.json \
  --output reports/solarmagix_ssl_a10_v1/baselines.json
```

这次训练记录的是 **NPZ 字节哈希**；不同 NumPy 版本重新写出的压缩包可能字节不同，即使数组相同。以上结果用从 A10G 取回的原始 NPZ 对齐计算，并核对了两端各分区的数组内容哈希。后续脚本同时记录数组内容哈希，避免压缩包元数据造成误判。

后续架构、容量与随机种子比较统一加 `--validation-only`，该模式不加载或评分留出电站；只用验证电站选择候选。例如：

```bash
python3 src/pretrain_solarmagix.py --data data/processed/solarmagix_8h.npz \
  --output reports/solarmagix_ssl_a10_width128_seed2027 \
  --device cuda --width 128 --depth 4 --seed 2027 --validation-only
```

### 验证区容量比较

在 A10G 上补跑宽度 64/深度 3 的另两个种子，以及宽度 128/深度 4 的三个种子。发现旧脚本的验证遮挡位置随训练种子变化，因此旧日志里的验证误差**不可直接横比**。把六个已存检查点统一用固定遮挡种子 `4101` 重新计算验证电站误差，未重新读取留出电站：

| 多尺度 CNN 容量 | 参数量 | 3 个种子固定遮挡验证 MSE | 平均 MSE |
| --- | ---: | --- | ---: |
| 宽度 64、深度 3 | 126,444 | 0.02849 / 0.02755 / 0.03028 | 0.02877 |
| 宽度 128、深度 4 | 597,260 | 0.02715 / 0.02314 / 0.02651 | **0.02560** |

大模型的平均误差比小模型低约 **11%**。新增五次训练各约 11–18 秒；检查点与固定遮挡结果已从实例取回本机。旧检查点仍是在不同遮挡集上选择的最佳轮次，因此这属于探索性容量比较，不是完整的公平预注册比较。代码现已把后续验证和测试遮挡种子固定为 `4101`/`4102`；真正判断迁移价值还需故障任务上的事件级和误报日级验证。

### 固定协议重训与集成

为排除上一轮选最佳轮次时遮挡位置不同的影响，已在 A10G 上按相同验证遮挡种子 `4101` 重新训练两种容量、每种三个随机种子。六个任务均使用 `--validation-only`，没有加载留出电站。权重与结果已复制回本机；集成在本机 Apple GPU 上用同一固定遮挡重新计算，CUDA/MPS 浮点差异约在末几位。

| 架构 | 种子 2026 | 种子 2027 | 种子 2028 | 三种子均值预测集成 |
| --- | ---: | ---: | ---: | ---: |
| 宽度 64、深度 3 | 0.03199 | 0.02755 | 0.02826 | 0.02614 |
| 宽度 128、深度 4 | **0.02254** | 0.02314 | 0.02651 | **0.02125** |

表中均为验证电站上的遮挡重建 MSE。大模型三个单模型的平均 MSE 为 **0.02406**，小模型为 **0.02927**，下降约 **18%**；大模型三种子集成又比其最佳单模型低约 **6%**。这是选择下一阶段编码器容量的证据，**不能**当作跨场站故障告警效果。该验证电站已经反复用于选型；真实迁移价值仍需新的故障事件与正常日期评估。
